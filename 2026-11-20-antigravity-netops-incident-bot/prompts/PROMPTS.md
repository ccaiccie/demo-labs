All prompts were typed into Google Antigravity 2.33 (Gemini 4 Neon) in the `netops-incident-bot` project.

## 1. Workspace rule and skill (Gemini 4 Neon, Low)

> Use the agy-customizations skill. Before we write any code, create workspace customizations for this new project, a NetOps incident bot. (1) An always-on rule in .agents/rules/netops-lab.md: services listen only on 127.0.0.1 on the host; syslog UDP port 5515 and web/API port 8097; never use ports 3000, 5514, 5678, 8088, 8090, 8099 or 9095 because they are already taken on this machine; Python 3.12 standard library only, no pip installs; every module needs unittest tests; never print, log or commit secrets or API keys; sample data must use documentation IP ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) and made-up hostnames. (2) A reusable skill in .agents/skills/replay-check/SKILL.md that runs the unit tests, checks that the Docker service is up, replays the sample logs with the replayer, then queries the REST API and summarizes the open incidents. Do not write any application code yet. Show me the files when done.

## 2. Core engine with the Orchestrator (Orchestrator, Neon)

> Build the core engine of a NetOps incident bot in this repo. Split the work into parallel workstreams and delegate them to subagents, with clear file ownership and API contracts. (1) incidentbot/parser.py: parse RFC 3164 syslog lines from Cisco IOS (%LINK-3-UPDOWN, %LINEPROTO-5-UPDOWN, %BGP-5-ADJCHANGE, %SEC_LOGIN-4-LOGIN_FAILED) and FortiGate key=value logs (event logs with logdesc, action=login status=failed, user, srcip) into a normalized Event (timestamp, host, vendor, kind, severity, interface, peer, user, src_ip, raw). (2) incidentbot/correlator.py: turn events into incidents: INTERFACE_FLAP (3 or more down/up changes of the same interface on one host within 120 seconds), BGP_NEIGHBOR_DOWN (opened when a neighbor goes Down, resolved when it comes back Up), AUTH_BRUTE_FORCE (5 or more failed logins from the same source IP within 60 seconds, across Cisco and FortiGate). Each incident has id, type, severity, host, key, first_seen, last_seen, count, status open or resolved, and a plain-text summary built from its events (no LLM). (3) incidentbot/store.py: SQLite storage for events and incidents (upsert, list with filters, get by id, resolve). (4) unit tests in tests/ for all three modules. Do not build the network service, Docker files or web page yet; another team will do that. At the end, verify everything with python -m unittest and give me a short summary.

## 3. Service, web UI, Docker and replayer with /swarm (Gemini 4 Neon, Medium)

> /swarm Turn the incidentbot engine in this repo (parser, correlator, store, already committed) into a running local service. One component per agent, in parallel, each owning its own files: A) service: incidentbot/server.py, a UDP syslog listener on 0.0.0.0:5515 inside the container that feeds parser, correlator and store, plus an HTTP server on 0.0.0.0:8097 with a REST API: GET /api/health, GET /api/incidents?status=open, GET /api/incidents/{id} (with its events), GET /api/events?limit=50, POST /api/incidents/{id}/resolve. B) web: a small status page served at / by the same HTTP server (static HTML and vanilla JS polling the API every 5 seconds): counters by severity, a table of open incidents with severity colors, and an incident detail view with its events and a Resolve button. C) docker: Dockerfile (python:3.12-slim) and docker-compose.yml, service incidentbot, published only on 127.0.0.1:5515/udp and 127.0.0.1:8097, SQLite on a named volume, healthcheck on /api/health. D) replayer: tools/replay.py that sends sample logs to 127.0.0.1:5515 over UDP with a speed option, plus samples/cisco_edge.log and samples/fortigate.log with realistic made-up traffic that should open at least one INTERFACE_FLAP, one BGP_NEIGHBOR_DOWN and one AUTH_BRUTE_FORCE incident. Every component gets unittest tests. Have a verifier run all tests, start the service locally with python on the same ports, replay both samples, check the API returns the expected incidents, then stop the local service. Do not run Docker; I will do that myself. Follow the workspace rule.
